# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Контекст репозитория

Веб-приложение для зубрёжки сербской лексики. Технологии: Spring Boot 3.2 + Thymeleaf, Kotlin 1.9 на JDK 21, Gradle (Kotlin DSL). 

Путь проекта должен оставаться ASCII: эмодзи или кириллица в пути ломают `gradle-wrapper.jar` (JNI percent-decoding падает).

## Команды

Сборка и запуск идут через Gradle Wrapper:

```bash
./gradlew bootRun          # запустить приложение (откроет http://localhost:8080 в браузере)
./gradlew build            # сборка с тестами
./gradlew test             # только тесты
./gradlew test --tests "ru.uvarov.flashcards.service.QuizServiceTest"   # одиночный класс
```

Toolchain в `build.gradle.kts` запрашивает JDK 21 — Gradle ищет его в системе. Если локально нет — нужно установить (например `brew install openjdk@21`) либо добавить `org.gradle.toolchains.foojay-resolver-convention` в `settings.gradle.kts` для авто-скачивания.

`main`-функция в `FlashcardsApplication.kt` после старта Spring'а вызывает `open http://localhost:8080` — приложение само поднимает страницу в браузере; это поведение macOS-специфичное (`ProcessBuilder("open", ...)`).

## Архитектура

Однопроцессное Spring-приложение, состояние держится в памяти, источник истины — текстовый файл словаря.

**Поток данных:**

1. `FileService` при `@PostConstruct` читает `src/main/resources/questions.txt` через classpath (`getResourceAsStream`), парсит в `Map<String, String> wordPairs` (rus → srb) и хранит весь список строк в `fileContent`. Файл загружается **один раз** на старте — изменения в `questions.txt` без перезапуска приложения не подхватятся.
2. `QuizService` берёт `wordPairs` из `FileService` и строит вопросы.
3. `QuizController` рендерит Thymeleaf-шаблоны (`quiz.html`, `words.html`).

**Endpoints:**

- `GET /`, `GET /quiz` — multiple-choice (4 варианта): по русскому слову выбрать сербский перевод. Отдельного меню нет, приложение сразу открывается на квизе. Первый вопрос приходит в модели (Thymeleaf инлайнит его в JS как JSON), дальше `quiz.html` сам рисует кнопки и тянет следующие вопросы через `GET /question` — страница не перезагружается. На сервер уходит только **первый** клик по вопросу: ошибка, исправленная следом, остаётся ошибкой. Клавиши: `1`–`4` — варианты (номер нарисован в углу кнопки, на тач-экранах скрыт), пробел — «Пропустить». Клавиши ловятся по `e.code` (физическая клавиша), а не по `e.key`: у владельца четыре раскладки (сербская кириллица/латиница, US, RussianWin). Цифры, кроме того, перехватывает расширение Vimium C в его Chrome: по умолчанию 0–9 там префикс-счётчик и до страницы не доходят, а пробел и Enter проходят. Владелец отключил цифры в расширении (2026-10-12); если цифры снова молчат, а пробел работает, первым проверить Vimium C, а не код. Переключатель «Сначала вспомнить» (`data-gate`, вкладки Quiz и Микс) прячет варианты за кнопкой «Вспомнил — показать варианты» (пробел): иначе ответ находится исключением знакомых вариантов, без вспоминания. Сверху счётчик комбо (правильных ответов подряд, общий для всех вкладок): живёт в `sessionStorage`, чтобы пережить переход на «Слова» и обратно; неверный клик и «Пропустить» обнуляют его (после неверного клика вопрос уже не засчитывается; «Пропустить» после найденного верного ответа просто листает дальше); «Удалить» комбо не трогает. Звуки верного/неверного ответа синтезируются Web Audio API прямо в `quiz.html` (файлов нет); верный перезвон с каждым шагом комбо на полтона выше, до октавы.
- `GET /type`, `GET /cards`, `GET /mix` — другие вкладки-тренажёры, та же страница `quiz.html` с атрибутом модели `mode`. «Ввод» (`type`): перевод печатается, проверка на сервере через `POST /typed`; пустой Enter — «не помню», после ошибки или «почти» Enter — дальше. Предложения (`sentence=true`) во «Вводе» не печатаются, а показываются карточкой. «Карточки» (`cards`): пробел открывает ответ, `1` — вспомнил, `2` — не вспомнил (без звука ошибки), уходит через `POST /answer`. «Микс» (`mix`): каждый вопрос в случайном из трёх режимов, один режим дважды подряд не выпадает.
- `GET /question` — следующий вопрос JSON'ом (`Question`: `word`, `answersList`, `retry`, `sentence`, `answerLatin`). `retry=true` — это повтор слова с недавней ошибкой, квиз показывает метку «Повтор». `answerLatin` — верный перевод латиницей, «Ввод» и «Карточки» показывают его под кириллицей.
- `POST /typed?word=<ru>&input=<text>` — ответ из «Ввода», возвращает `Verdict` JSON-строкой (`CORRECT`/`ACCENT`/`WRONG`) и записывает как обычный ответ (`ACCENT` засчитывается). `AnswerChecker` сравнивает в латинице: кириллица → латиница однозначна, обратно нет (nj бывает и н+ј). Регистр, пунктуация и пробелы не важны; принимается любой вариант через `,` или `/`; совпадение без диакритики (`č ć → c`, `š → s`, `ž → z`, `đ → dj`) — `ACCENT`, буквы подсвечиваются в ответе.
- `GET /words` — редактируемый список словаря: пары рендерятся как два `<input>` (ru, srb) с ×-кнопкой; `#`-заголовки (показываются без `#`: `DictionaryLine.Heading.text` хранит название категории без решётки) и пустые строки сохраняются как визуальные разделители. Счётчик `wordCount` сверху = `wordPairs.size`. Над списком поле-фильтр (по обеим колонкам, на клиенте; при активном фильтре заголовок категории виден, только если под ним есть совпадения). Справа от пары — вес слова (`+N` зелёным, `−N` красным, пусто при 0). Изменения уходят через `PUT /word` на `change`-эвент инпута, удаление — через `DELETE /word`.
- `DELETE /word?word=...` — удаляет пару по русскому ключу. Дёргают `quiz.html` (кнопка «Знаю — удалить») и `words.html` (×). `FileService.deleteWord` убирает пару из in-memory и перезаписывает `questions.txt` через `quiz.word-write-filename`.
- `PUT /word?oldRu=...&newRu=...&newSrb=...` — обновляет пару. `FileService.updateWord` валидирует blank/«=»/«#»/коллизию ключей, заменяет совпадающую строку в `fileContent` на `newRu=newSrb` (нормализует пробелы вокруг `=`), перезаписывает файл.
- `POST /word?newRu=...&newSrb=...` — добавляет пару. `FileService.addWord` валидирует через тот же `validateNewPair` + проверку дубликата, аппендит `newRu=newSrb` в конец `fileContent`, перезаписывает файл. Фронтенд (`words.html`, ghost-row сверху списка) на успех динамически вставляет ряд в конец `.words-list` и инкрементит счётчик, без перезагрузки.
- `POST /answer?word=<ru>&correct=<bool>&recall=<bool>` — фиксирует ответ на квиз или оценку карточки (`recall=true`: перевод вспомнен без вариантов, по умолчанию `false`). `QuizService.recordAnswer` ставит слово с ошибкой в очередь повторов, передаёт ответ в `FileService.recordAnswer` (вес ±1 в `questions.txt`) и в расписание показов (`ProgressService.record`). Исключение — верный ответ на вопрос-повтор: ни вес, ни расписание не трогаются, иначе ошибка снова стирается. Дёргает `quiz.html` один раз на вопрос (первый клик в квизе, оценка карточки).

**Тема и звук (`static/prefs.js`):** подключается в `<head>` обеих страниц без `defer` и до отрисовки ставит на `<html>` `data-theme` (`dark` по умолчанию / `light`), `data-sound` (`on`/`off`) и `data-gate` (`off`/`on`, «Сначала вспомнить») из `localStorage`. Переключатели — иконки в шапке (звук только на квизе). Палитра — gruvbox (значения из `morhetz/gruvbox`, `colors/gruvbox.vim`), CSS-переменные в `:root` (тёмная) и `:root[data-theme="light"]`. В светлой теме нейтрали (фон, карточки, рамки) — холодные серые: кремовые light0..light4 владельцу не нравятся; акценты — faded-цвета gruvbox.

**Формат словаря (`src/main/resources/questions.txt`):**

- Строки `русское=сербское` ИЛИ `русское=сербское=вес` (вес — целое, может быть отрицательным).
- Регистр и диакритику сохранять как есть. Сербская сторона может содержать варианты через запятую: `неделя=седмица, недеља`.
- Строки, начинающиеся с `#` — это категории-разделители (`#Дни недели`); пропускаются при парсинге, но видны в `/words`.
- Пустые строки — допустимы (пропускаются).
- Строка без `=` (кроме `#` и пустых), с >2 `=`-разделителями, или с не-числовым весом — роняет приложение на старте через `IllegalArgumentException`.
- Один и тот же сербский перевод у двух ключей **одной категории** даёт в квизе две одинаковые кнопки (одна «неверная»). Синонимы склеивать в один ключ через запятую (`встреча, совещание=састанак`), а не заводить вторую строку.

**Расписание показов (`Fsrs` + `ProgressService` + `QuizService.pickScheduled`):**

Алгоритм — FSRS-6, как в Anki: формулы и параметры по умолчанию перенесены из py-fsrs (MIT), `FsrsTest` сверяет перенос с её значениями. Упрощения: нет шагов заучивания в минутах (их роль играет очередь повторов) и разброса интервалов; интервалы — целые дни, «сегодня» — по `Clock`-бину. Оценки: ошибка или «не помню» → `AGAIN`; верный выбор из вариантов → `HARD` (узнать легче, чем вспомнить); верный ввод (и без диакритики) и «Вспомнил» в карточке → `GOOD`.

Состояние слова — в `quiz.progress-filename` (`./src/main/resources/progress.txt`, читается и пишется по этому пути, не через classpath), строки `русское=stability=difficulty=последний ответ=срок`; у новых слов строки нет. Запись атомарная, как у словаря. `FileService` при удалении и переименовании слова уводит его прогресс за собой.

Порядок вопросов: 1) очередь повторов в памяти `QuizService` — слово с ошибкой возвращается на `quiz.retry-after`-м (по умолчанию 4-м) следующем вопросе; удалённые и переименованные слова из очереди выпадают, после перезапуска она пуста; 2) слова, которым подошёл срок, — первым самое вероятно забытое; 3) новые, случайно; 4) если нет ни тех, ни других, — досрочно самое вероятно забытое. Последние `retry-after` заданных слов в выбор не попадают, иначе пропущенное слово выпадало бы снова сразу. `Question.dueCount` — сколько слов к повторению, квиз показывает его сверху.

Вес = статистика «верно минус неверно» для «Слов», на выбор слова больше не влияет. Правильный ответ → +1, неправильный → -1, по умолчанию 0. При весе 0 строка пишется без суффикса (`ru=srb`), при ненулевом — с (`ru=srb=N`). `updateWord` сохраняет вес при переименовании ключа.

**Генерация multiple-choice (`QuizService.getQuestion`):**

Размер списка ответов — `quiz.answer-size` из `application.yaml` (по умолчанию 4). Один правильный + дистракторы, добираемые `fill` тремя тирами, от сильного к запасному: 1) та же категория (`#`-заголовок) и тот же тип записи по сербской стороне (слово / фраза из 2–3 слов / предложение — 4+ слов или кончается на `.`/`?`, см. `classify`); 2) тот же тип из любой категории; 3) что угодно, лишь бы набрать размер. Внутри каждого тира первыми идут слова, чей сербский перевод **начинается на ту же букву**, что и правильный, — это удерживает квиз от «угадай длинное слово против коротких». `Answer.equals/hashCode` сравнивают по паре (word, translate), а не по `correct` — это важно для дедупликации в `fill`.

**Запись словаря (`FileService.persist`):**

`quiz.word-write-filename` в `application.yaml` указывает на `./src/main/resources/questions.txt` — относительный путь от cwd при запуске. Это значит: при `./gradlew bootRun` из корня репо изменения пишут **прямо в исходники**. Из jar в произвольной cwd работать не будет — придётся переопределять путь. Все мутации помечены `@Synchronized`. Запись атомарная: сначала во временный `<name>.tmp`, потом `Files.move(..., ATOMIC_MOVE, REPLACE_EXISTING)` — крэш мид-write не попортит словарь.

**Обработка ошибок:**

`GlobalExceptionHandler` (`@ControllerAdvice`) маппит `IllegalArgumentException` (от `require()` в `FileService`) на `400 Bad Request` с телом-сообщением. Фронтенд читает `response.text()` и показывает в alert. `IllegalStateException` (от `check()`) остаются 500 — это «не должно случаться».

## Соглашения по коду

- Kotlin `data class` для DTO (`Answer`, `Question`).
- Lombok не используется — стандартные средства Kotlin (data class, primary constructor) закрывают потребность.
- Логгер — через `org.slf4j.LoggerFactory.getLogger(...)` в companion object или top-level `private val`.
- Spring требует `kotlin("plugin.spring")` (открывает `@Component`/`@Controller`/`@Service` для proxying) и `kotlin-reflect` — оба уже подключены.
- Конфигурация — через `@Value("\${quiz.*}")` в primary constructor, не через `@ConfigurationProperties`. Знак `$` в строке Kotlin экранируется как `\$`.
- Тесты — JUnit 5 + mockito-kotlin (`mock<T>()`, `whenever()`). Имена методов в backtick'ах по схеме `methodName - condition - expectedResult`. Юнит-тесты `FileServiceTest`, `QuizServiceTest` гоняют рандомизированные тесты по `RUNS = 100` итераций — не уменьшать без причины, это страховка от флака.
- Тестовый словарь живёт в `src/test/resources/test-words.txt`, отдельно от боевого `questions.txt`.
